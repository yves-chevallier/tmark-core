# 03 — The intermediate representation

Crate: `tmark-ir`. This crate is the **single source of truth** for what a
document is. Everything else reads or writes these types. It contains no
parsing and no rendering.

## Design rules (inherited from TeXSmith's IR, kept)

1. **No backend strings in the tree.** The only escape hatches are
   `RawInline` / `RawBlock` with a `format`. A writer ignores raw nodes of
   another format.
2. **Pure tree, no side state.** Citations, footnote bodies, counters, index,
   "needs shell escape" and friends are derived by registries and writers,
   never stored in nodes.
3. **Immutable, structural equality.** Nodes are plain values; children are
   `Vec`; `PartialEq` is by value *excluding* spans and ids (a separate
   `eq_with_spans` exists for tests).
4. **Typed node only when structured fields matter to a writer.** Everything
   else is `Div` (block) or `Span` (inline) with `Attrs`. A typed node needs
   a fixture and at least one writer that treats it specially.
5. **Serializable.** `serde` on every type; `schemars` on the front matter
   and on the IR so that JSON Schema documents both. This is how TeXSmith,
   the LSP and tests exchange documents.

## Shape

```rust
pub struct Document {
    pub file: FileId,
    pub front_matter: FrontMatter,      // typed keys + raw text + extra JSON
    pub blocks: Vec<Block>,
    pub abbreviations: Vec<Abbr>,       // `*[HTML]: …` definitions, document-level
    pub footnotes: Vec<Footnote>,       // `[^1]: …` definitions, document-level
}

pub struct Meta { pub id: NodeId, pub span: Span }   // on every node

pub enum Block  { Para(Para), Header(Header), … }     // one variant per catalogue entry
pub enum Inline { Str(Str), Emph(Emph), … }
```

Every variant struct starts with `meta: Meta`. Enums, not trait objects:
matching is exhaustive, serde is trivial, and adding a variant is a compile
error everywhere it matters (which is the point).

## Node catalogue

Names follow the spec's node catalogue and TeXSmith's `texsmith.ir.nodes`,
so that the Python side and this crate speak the same names. Fields are the
minimum a writer needs; layout hints are attributes, not fields, unless a
writer must branch on them.

### Attributes

```rust
pub struct Attrs { pub id: Option<String>, pub classes: Vec<String>, pub kv: Vec<(String, String)> }
```

Order is normalised by the printer (`#id`, `.class`, keys in source order).
The three universal attributes (`#id`, `lang`, `media`) have accessors; they
are still stored in `Attrs` so unknown hosts round-trip.

### Tables

`TableModel` is the semantic model TeXSmith already validates for `yaml
table`: columns (recursive groups, `align` as `l|c|r|j`, `width`,
`width-group`), rows of cells with `rows`/`cols` spans and `~` absorption,
separators with labels, footer, named-row mode, the `table:` section
(`width`, `placement`, `long`). The Rust definition is a port of
`texsmith.extensions.tables.schema` and is the single definition: every
type and field names the Python class and field it mirrors in its doc
comment (`crates/tmark-ir/src/table.rs`), and the Python side is
regenerated from the JSON schema. Pipe tables and grid tables lower to the
same model (rung 1 and 4 of the spec's ladder produce a model with no spans
and no groups). A column carries its header twice by design: `name` is the
plain text, which is the key of named-row mode and what a diagnostic names
the column by, and `title` the same header parsed as inline Markdown, set
only when it carries markup a string cannot hold (spec §Table: "Inline
Markdown survives inside cells in all forms"); the writers prefer `title`. A `Table` or `TableConfig` whose fence the parser reported
a `table-*` diagnostic on keeps the fence body in `source`: the model is a
best effort for writers, the printer writes the source back as typed.

## Identity and spans

```rust
pub struct FileId(u32);
pub struct Span { pub file: FileId, pub start: u32, pub end: u32 }   // byte offsets
pub struct NodeId(u32);
```

- `Span` covers the *whole* construct including its sugar (`{aside}[x]`, not
  just `x`). Sub-spans that tools need (the key of a reference, the id in an
  attribute list) are stored as fields of the node, as `Span`s.
- `NodeId` is unique within a file and increases in document order, but it
  is not dense (the lowering allocates ids at three sites; TeXSmith decision
  X6 chose to state the weaker guarantee rather than change them). Passes
  that rebuild a document keep the ids of nodes they did not create; new
  nodes get ids above the previous maximum of every file. This is what lets
  a source map survive TeXSmith's passes.
- `Document::line_index()` gives line/column; nodes never store them.

## Front matter

`FrontMatter { raw: String, doc: Meta, keys: Keys, extra: serde_json::Value }`
with `Keys` the typed subset the spec says TMark reads: `title`, `subtitle`,
`authors`, `date`, `id`, `lang`, `epigraph`, and the `press` namespace with
`base_level`, `declare` (counters, admonitions, glossary, acronyms),
`sources` (bibliography, crossrefs), `features`. Any key may sit at the root
or under `press`; `press` wins (spec §Front matter). Keys TMark does not own
(`template`, `callouts`, `code`, `slots`, `refs`, `details`, …) are preserved
in `extra` untouched.

The `schemars` derivation of `Keys` is the JSON schema the LSP completes
against and that TeXSmith merges with its own `press` schema. Deprecated
top-level spellings (`bibliography`, `counters`, …) are accepted by a custom
deserializer that records a `deprecated` diagnostic.

## Closed registries (data, not code)

`tmark_ir::registry` holds the tables every other crate reads:

- `ROLES`: name, argument style (`Content`, `ContentMany`, `Argument`),
  principal key, accepted keys, node produced, deprecation.
- `NODE_WORDS`: `code`, `table`, `table-config`, `image`, `raw`, plus the
  per-language default (`mermaid` → `image`).
- `PREFIXES`: the predeclared counter prefixes with name, scope, `ref`
  template.
- `ADMONITIONS`: built-in types and the predeclared theorem types.
- `CONTAINERS`: the closed container registry of spec §Div (`figure`,
  `aside`, `tabs`, `tab`, `multicolumn`, `landscape`, `div`), with the node and the
  keys each takes; admonition types are the other container names. Any
  other `::: name` is `container-unknown` and still a `Div`.
- `TEX_LOGOS`: the words of spec §TeX logos, set as logos by the writers
  under the feature `typography.tex-logos`; no node.
- `FEATURES`: dotted name, default, spec section.
- `DEPRECATIONS`: deprecated spelling → canonical, status, horizon.
- `FRAGMENTS`: the fragment contracts a writer may name in
  `Requires.fragments` (`07-writers.md`): name, the macros and environments
  the fragment `provides`, the LaTeX `packages` it implies, `shell_escape`,
  description. Rows and names are TeXSmith's
  `specs/migration/fragment-contracts.md` §2; `provides` entries are unique
  across rows (a macro has one owner), and TeXSmith checks a replacement
  fragment against them.
- `KEY_LABELS`: keystroke name → label (`ctrl` → `Ctrl`, `arrow-up` → `↑`),
  the table every writer renders `Keystroke` with; a name without a row is
  written in uppercase. Ported from TeXSmith's `keystroke.tex` partial, with
  the PyMdownX aliases authors type (`ctrl`, `cmd`, `del`, `escape`,
  `return`). Labels are backend-neutral text; the LaTeX writer maps the
  arrows and the backslash itself.

`tmark_ir::emoji` holds the `gemoji` shortcode table (spec §Emoji and icon
shortcodes): `EMOJI`, sorted `(shortcode, character)` pairs generated by
`scripts/gen-emoji.py` from `github/gemoji`'s `db/emoji.json` (the header
of `emoji/table.rs` names the source), `emoji(name)` by binary search, and
`ICON_SETS` / `is_icon` for the four Material icon prefixes. The crate
stays dependency-free.

Each table is a `const` slice of a small struct. Grammars, completion lists,
lint messages and documentation are generated from them; no other crate
hard-codes a role name. `cargo run -p tmark-ir --example registries`
writes the tables the editor grammar and TeXSmith read to
`editors/vscode/scripts/registries.json`.

## Walking and mapping

Two functions, nothing more: `walk(&Document, &mut impl FnMut(NodeRef))`
pre-order, and `map(Document, impl FnMut(Node) -> Node)` rebuilding. Visitors
with one method per node type are not provided; matching on the enum is the
visitor.

## Serialization

`Document` serialises to JSON with `#[serde(tag = "type")]` on the enums, so
a node reads as `{"type": "Emph", "id": 12, "span": [..], "content": [...]}`.
This is the format `tmark-py` returns when asked for JSON, the format tests
compare, and the format `spec/conformance/` fixtures store. A schema is
generated to `crates/tmark-ir/schema/ir.json` by `cargo run -p tmark-ir
--example schema` and committed.

## Implementation notes (milestone 1)

Decisions taken in `tmark-ir` that refine the text above; the code is the
reference for the shapes, this list says why they differ from the first draft.

- The inline `Span` node is the Rust type `SpanNode` (the source range owns
  the name `Span`); its JSON tag stays `"Span"`. The inline `Code` node is
  re-exported as `CodeInline` because `Code` is the diagnostic code enum.
- `Comment` is one struct used by `Block::Comment` and `Inline::Comment`.
- `FrontMatter.meta` replaces the draft's `doc: Meta`; `Keys.title` is
  `Option<Option<String>>` so that `title: null` (spec §Header: opt out of
  title promotion) differs from an absent title.
- "press wins" applies per top-level key: the root value is dropped, not
  merged. Deprecated top-level spellings are accepted at the root and under
  `press`, never overwrite a canonical value, and are listed in
  `FrontMatter.deprecated` for the diagnostics.
- Structural equality: `Meta::eq` is always true, so derived `PartialEq`
  ignores ids and spans everywhere; `Meta::same` and `eq_with_spans` compare
  identity. `Meta` has no `Eq`/`Hash`.
- `TableModel` rows are a dense leaf matrix: one `Cell` per leaf column,
  spanning cells carry `rows`/`cols`, covered slots are `absorbed` cells.
  TeXSmith's row `label` is the first leaf cell (the first top-level
  column is the label column); `named` records the YAML row mode. Python
  builds the same matrix on validation (`build_matrix`) but keeps the
  written rows; here the matrix is the model and the printer regroups it
  (design 04, wave 1 notes).
- Row semantics (wave 1, decision X9; port of `parse_table` in
  `tmark-syntax::lower::table_yaml`): a positional row has one item per
  top-level column. A group's item is a list of its leaves; a scalar fills
  the column's remaining leaves; a rich cell `{value, rows, cols, align}`
  spans from the cursor, and the slots its column span absorbs are not
  written; every slot a row span absorbs is written `~` (also inside a
  group list); a `~` elsewhere is an empty cell. A named row
  (`- Label: {Column: value}` or `- {label, cells}`) addresses the
  top-level data columns by name, an omitted column is empty. Where the
  Python validator deviates by accident the documented rule wins and the
  Python reading is accepted as a fallback (design 12, C30).
- Validation is split by representability: what the matrix cannot hold
  (unknown keys, ragged rows, span collisions, unknown named columns,
  unknown align) is a parse diagnostic and sets `source`; what it holds but
  a backend refuses (placement letters, percentage ranges, widths over
  100 %) is a lint rule (design 05).
- Enum values serialise in `snake_case` (`"kind": "table"`, `"position":
  "after"`); tagged enums use `"type"`. Defaults are skipped, so a fixture
  states only what matters.
- `map` is not provided (no pass needs it yet); `walk` is.
- Sub-spans (the key of a `RefItem`, the id of an attribute list) are not
  stored yet; the LSP milestone adds them where navigation needs them.
- A generated image (`python image`, bare `mermaid`) is an `Image` with an
  empty `src` and the attributes `generate=<lang>` and `code=<fence text>`,
  plus the fence options. A dedicated field is a candidate once the
  writers show what they need.
- `Space` exists but the parser does not emit it: whitespace stays inside
  `Str`. Writers implement the zero-width collapse by inspecting `Str`
  boundaries (design C8).
- A block `::: aside` lowers to `Para([Aside { content: blocks }])`; an
  inline `{aside}[…]` to `Aside { content: [Plain(inlines)] }`, so one node
  covers both forms.

## Implementation notes (C31–C42 wave)

- `ProgressBar` is an inline node (spec §ProgressBar: a bar fits a table
  cell); `value` is an `f64` percentage, clamped by the parser, and
  `value_text` / `head_text` are the one spelling of the number and of the
  head, shared by the printer and by the parser's fix for the deprecated
  fraction form.
- Tabs are `Div{name=tabs}` holding `Div{name=tab}` with `title=` as a
  plain attribute (no inline title, unlike `Admonition`): the printer and
  the writers read `attrs.get("title")`.
- An icon shortcode is `Span{.icon media=web}` around one `Str` holding
  the shortcode; an emoji is the character inside `Str`, so neither adds
  a node type.
- The implicit id of a heading is never in the IR: `tmark-registry` derives
  it (`Label::implicit`), the printer never sees it.
